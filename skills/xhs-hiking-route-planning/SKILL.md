# 小红书信息源的重装徒步路线规划

## Overview

以社交平台真实实走帖为核心信息源，产出"可信、有时效标注、站在出发者视角"的徒步路线攻略。核心原则：**单帖不可信，交叉才作数；人流结论必须绑定"最近的真实周末"；稳定维度与时效信息分离记录。**

## 流程

### 1. 先问偏好，再搜索

未确认以下信息前不要开始搜索：出发城市、目的地倾向（没有就按主题搜）、出行日期与几天几夜、玩法主题（赏秋/看雪/看海/星空/日出云海）、体力与重装经验、是否强制公共交通。

### 2. 搜索策略（工具无关）

- 关键词组合：`地名 + 徒步/重装/露营/攻略/避雷/人多/交通`；地名用本地叫法（如"太子尖"而非仅"临安"）
- 每个候选路线至少读 2–3 帖：攻略帖（数据）+ 实走帖（时效验证）+ 避雷帖（反面清单）
- 帖子 ID 前 8 位十六进制 ≈ Unix 时间戳，可快速判断发帖新旧、排序找最新
- 公交班次、预约渠道等**公共信息用官方渠道**（政务/客运公司/公众号）核实，UGC 只作线索
- 图片：提取帖子图片链接时注意 CDN 签名链接有时效，下载留存本地；视频帖无图片文件，可抓视频帧替代；拿到图片后务必目检（区分风景照/轨迹图/自拍/占位图）

### 3. 信息可信度核查（最重要的规则）

| 陷阱 | 核查方法 |
|------|----------|
| 工作日/调休日实走被当成"周末人少"证据 | 每条人流结论问：发帖人**哪天**上山？那天是工作日、调休、周末还是节假日？作者身份（学生/自由职业）影响代表性 |
| 攻略汇编帖数据过时 | 数据与最近实走帖对照；以实走帖为准 |
| 找搭子帖/wishlist 帖冒充实况 | 区分"我要去"与"我去过了"（看正文时态、日期） |
| 单帖好恶当结论 | 至少 2–3 帖交叉；有踩雷帖必须读 |
| 人少/爆满结论过期 | 人流是**快照不是属性**：爆满必发帖、冷门不发帖（不对称性）——某线近期零新帖=大概率仍冷门（置信中等）；某线突然出现密集劝退帖=窗口关闭 |

### 4. 路线必查维度（产出文档的章节骨架）

1. **路线数据**：里程/爬升/最高海拔、不同走法变体、危险路段（湿滑/陡降/夜路/蛇虫/岔路迷路/无信号）、轨迹获取方式
2. **露营地**：位置、平整度与容量、风、是否收费、旺季是否抢（"晚到没位置"要写明）
3. **水源**：最后补水点位置与距营地距离、可饮性（过滤/煮沸）、按无补给兜底规划
4. **温度与装备**：按海拔折算夜温（山顶约比山下低 6–10°C），给出睡袋温标与分层清单——这是用户常漏、但没有就 unsafe 的维度
5. **交通时间账**：高铁→地铁/公交（班次+票价+官方公众号）→打车/拼车（价格+联系人，如客栈老板代约）→ 逐段耗时；标注"单点依赖"风险（如只能靠某客栈接送）
6. **管控与人员**：预约/门票/限流（小程序名+价格）、护林员、防火期明火、商贩
7. **人流实况**：最近 1–2 个周末的实况，区分工作日/周末/节假日

### 5. 特殊信息 vs 规划信息（分开写）

- **特殊信息**（时效快照，会失效）：近期突然爆满、预约管控收紧/放松、封路、灾害——单独成节，标注"截至日期"，并写明"出发前搜最新帖复核"
- **规划信息**（稳定维度）：上面第 4 节的全部内容——按正常章节写
- 判断标准：这条信息 3 个月后还成立吗？不成立的就是特殊信息。

### 6. 产出

- **主推 1 条 + 备选 1 条**，备选单独成文档，结构相同：TL;DR → 路线概况 → 交通（含时间账）→ 管控 → 温度装备 → 特殊信息 → 行程模板（D1/D2 时间轴）→ 信息源（原帖链接必须保留完整参数）→ 配图
- 排序给理由；明确"周末不可行"的线单独警示
- 视角：写"你周六几点出门、几点到营地"，不是写百科

## Common Mistakes

- 跳过偏好访谈直接搜索 → 返工
- 把单帖结论写进正文不加来源 → 必须每条关键信息挂原帖链接
- 人流结论不带日期 → 等于没写
- 只写稳定信息不写特殊信息 → 用户撞上管控/爆满
- 忘记温度/水源等"用户没提但致命"的维度
